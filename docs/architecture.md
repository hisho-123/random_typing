# 構成・データ設計

## 1. 初期構成

初期リリースは、静的に配信するフロントエンドだけで成立させる。
ブラウザー内で問題生成、ローマ字判定、時間計測、成績計算を完結する。

```text
仕様の参照元：本リポジトリ random_typing
  └─ 将来の実装先：random_typing_frontend
       ├─ 設定・プレイ・結果の表示
       ├─ 問題生成
       ├─ ローマ字判定
       ├─ ゲーム状態・時間の管理
       └─ 成績計算
```

フレームワーク、パッケージ管理、ホスティングは未選定とする。
API、データベース、認証、バックエンドリポジトリは初期リリースの必須要素としない。

## 2. 実装の責務

以下は論理的な責務であり、ファイル名やクラス名を指定するものではない。

| 責務 | 入力 | 出力・役割 |
| --- | --- | --- |
| 設定の検証 | 選択値 | 許可された時間・文字数だけを持つ設定 |
| 問題生成 | 文字数、乱数源 | 71 文字の集合から生成した平仮名列 |
| 入力判定 | 問題、現在の判定状態、キー | 正解 / ミス / 対象外、次の判定状態、完了の有無 |
| ガイド生成 | 問題、残っている入力経路 | 表示用ローマ字、受理済み部分、確定した平仮名の範囲 |
| ゲーム管理 | 開始・中止・キー入力・現在時刻 | 状態遷移、現在の問題、集計値 |
| 成績計算 | 正しいキー数、ミス数、設定時間、完了問題数 | 正確率・KPM を含む結果 |
| 画面表示 | 現在のゲーム状態 | 各画面の描画、操作イベント、フォーカス管理 |

乱数源と時計は検証時に差し替えられる形にし、固定した問題や期限の境界を再現できるようにする。
入力判定・成績計算は画面の描画処理から分離し、画面更新の頻度で成績が変わらない構成にする。
実装時のコメントには、候補を途中で捨てない理由や、キー判定前に期限を確認する理由など、コードだけでは分かりにくい根拠を日本語で記す。

## 3. データ

すべてメモリー上で管理する。以下の名前は概念を示すものであり、実装言語の型宣言ではない。

### 設定 `GameSettings`

| 項目 | 制約 |
| --- | --- |
| `durationSeconds` | 30 / 60 / 120 のいずれか |
| `questionLength` | 5 / 8 / 12 のいずれか |

### ゲーム状態 `GameSession`

| 項目 | 内容 |
| --- | --- |
| `status` | `ready` / `countdown` / `playing` / `finished` |
| `settings` | 今回の設定 |
| `countdownStartedAt` | カウントダウンの開始時刻。開始前は未設定 |
| `startedAt` / `deadline` | プレイ開始時刻・期限。プレイ開始前は未設定 |
| `currentQuestion` | 現在の平仮名列。プレイ開始前は未設定 |
| `acceptedRoman` | 現在の問題で受理したローマ字列 |
| `matcherState` | 有効な複数の入力経路と、各経路の現在位置 |
| `correctKeys` / `missKeys` | ゲーム全体の正しいキー数・ミス数 |
| `completedQuestions` | ゲーム全体の完了問題数 |

残り時間は `deadline` と現在時刻から、正確率・KPM は集計値から導出する。
「ん」の曖昧な入力を扱うため、判定状態を単一のローマ字文字列と位置だけに制限しない。

### 結果 `GameResult`

| 項目 | 内容 |
| --- | --- |
| `settings` | 今回の設定 |
| `correctKeys` / `missKeys` / `completedQuestions` | 時間切れで確定した集計値 |
| `accuracy` / `kpm` | [ゲーム仕様](game-rules.md)の式から求めた数値 |

結果は時間切れ時に一度だけ確定し、その後の入力やタイマーでは更新しない。

## 4. データの寿命と例外処理

- ページを再読み込み・閉じると、設定・進捗・結果をすべて失う。
- Cookie、localStorage、IndexedDB にゲームの情報を保存しない。
- タイマー・イベント購読は中止・終了・再挑戦時に整理し、前回ゲームの処理を次回に適用しない。
- 設定値が許可リスト外の場合は、ゲームを開始せず初期設定に戻す。
- 問題生成や判定データに不整合が発生した場合は、プレイを中止して設定画面に戻り、「練習を開始できませんでした。もう一度お試しください」と表示する。正常終了の成績として扱わない。
- 通信失敗をゲーム内の回答ミスとして扱わない。初回の資材取得失敗への対応は配信方式を決める際に定義する。

## 5. 関連リポジトリとの整合性

| 領域 | 初期リリースへの影響 |
| --- | --- |
| 仕様 | 本リポジトリが要件・挙動・受け入れ基準を管理する。命名ルールに沿う候補名は `random_typing_docs` |
| フロントエンド | 新規実装時に本仕様を参照する。入力対応表・時間境界・成績計算が主な整合性の確認対象 |
| バックエンド | 既存実装は確認できておらず、初期リリースの API 契約も設けない |
| インフラ | 静的資材の配信先が必要。公開先・URL・環境構成は未決定 |

同サービスの実装リポジトリは参照可能な範囲に存在せず、今回の変更は仕様文書のみである。
将来、成績保存・会員登録・ランキングを追加する場合は、保存項目、API、認証、個人情報の扱いを先に仕様へ追加する。
